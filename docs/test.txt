# 五子棋前端开发任务规划

> 依据 1.txt 设计文档拆解。前后端分离，本文档只覆盖前端；
> 一期目标 = **本地双人完整可玩 + 全部页面骨架就位**，后续每期只"点亮"功能。

---

## 一、全局技术约定（开工前定死，避免返工）

| 项 | 约定 |
|---|---|
| 技术栈 | 原生 HTML / CSS / JS（ES6+），无框架、无构建工具，双击 index.html 即可运行 |
| 页面结构 | 多页面：index / game / login / rank / history |
| 布局 | 移动端优先，页面容器 `max-width: 480px` 居中，PC 两侧深灰留黑边 |
| 配色 | 背景 `#2B2B2B`；棋盘 `#E8C286`；黑子 `#1A1A1A` / 白子 `#F8F8F8`；强调朱红 `#C0392B` |
| 色彩管理 | 全部颜色走 `style.css` 顶部的 CSS 自定义属性（`--bg`、`--board`、`--accent`…），一处改全局生效 |
| 棋盘 | 15×15，Canvas 绘制，`devicePixelRatio` 适配保证高清屏不糊 |
| 事件 | 统一用 Pointer Events（鼠标 + 触摸一套代码） |
| 音效 | 优先用 Web Audio API 合成（落子"嗒"声），避免依赖素材文件；设置里可关 |
| 数据 | 一切需要后端的数据（用户、战绩、排行）在 `api.js` 里留 mock 接口，页面只调接口不关心来源 |

**目录结构**（按 1.txt）：

```
gomoku-web/
├── index.html      首页
├── game.html       对局页（核心）
├── login.html      登录/注册
├── rank.html       排行榜
├── history.html    战绩
├── css/style.css
├── js/
│   ├── board.js    Canvas 棋盘绘制与交互（纯渲染，不含规则）
│   ├── game.js     对局逻辑（规则、回合、胜负）
│   ├── api.js      fetch 接口封装（一期全部是 mock）
│   └── common.js   弹窗、toast、用户信息条、底部导航等公共组件
└── assets/         图标（尽量用内联 SVG，少放文件）
```

**分层原则**：`board.js` 只管"画"和"点哪了"，不知道规则；`game.js` 只管规则和状态，通过回调驱动 board。这样二期把判定挪到后端时，board 一行不改。

## 二、任务分解（按里程碑）

### M0 · 项目骨架（约 0.5 天）

- [ ] 建目录、建空文件，5 个 HTML 全部引好 css/js
- [ ] 所有页面统一 `<meta viewport>`（`width=device-width, initial-scale=1`），body 上加 `touch-action: manipulation` 消除移动端 300ms 延迟和双击缩放
- [ ] `style.css`：CSS reset + 自定义属性色板 + `.page` 容器（480px 居中）+ 顶部栏 / 底部导航 / 按钮的公共样式
- [ ] `common.js`：
  - [ ] 通用弹窗组件 `showModal({title, body, buttons})`（半透明遮罩 + 居中卡片，结算框、规则说明、退出确认全复用它）
  - [ ] toast 轻提示
  - [ ] 底部导航生成函数（当前页高亮）
- [ ] **验收**：任一页面打开，深色背景 + 480px 容器 + 底部导航可见，弹窗组件可弹出关闭

### M1 · 棋盘渲染与交互 board.js（约 1 天，核心难点）

- [ ] Canvas 初始化与自适应：
  - [ ] 尺寸随容器宽度缩放（`100vw` 上限 480px 内），`window.resize` 时重绘
  - [ ] HiDPI 处理：`canvas.width = cssSize × dpr`，`ctx.scale(dpr, dpr)`，否则手机上棋盘发虚
- [ ] 绘制棋盘：木色底 `#E8C286`、15 条横线 + 15 条竖线、5 个星位（天元 + 四星，索引 3/7/11）
- [ ] 坐标换算：`格点 = round((像素 - 边距) / 格宽)`，双向换算；点击容差取最近交叉点
- [ ] 绘制棋子：径向渐变高光（黑子左上高光、白子微灰渐变），落子缩放动画（requestAnimationFrame，约 150ms 从 1.3→1.0）
- [ ] 最后一手标记：最新棋子上叠加朱红小圆点
- [ ] hover 预览：仅 `pointerType === 'mouse'` 时在悬停格点画半透明棋子，移开清除
- [ ] 触摸落子：canvas 上 `touch-action: none` 防止落子时页面滚动
- [ ] 对外接口（给 game.js 调）：`draw(stones)` 全量重绘、`onCellClick(cb)` / `onHover(cb)` 回调、`highlightWin(cells)` 五连高亮 + 红线、`lock()/unlock()` 锁盘
- [ ] **验收**：手机和 PC 上棋盘清晰不糊；点击交叉点能落子（临时测试代码）；hover 有预览；最后一手有红点

### M2 · 对局逻辑 game.js（约 1 天）

- [ ] 状态：`board[15][15]`（0 空 / 1 黑 / 2 白）、落子历史数组、当前执子方、手数、开始时间
- [ ] 计时器：顶部 `⏱ mm:ss`，用 `Date.now()` 差值计算而非每秒 +1（切后台回来时间仍准确）
- [ ] 落子流程：校验空位 → 更新状态 → 落子动画 + 音效 → 检查胜负 → 切换回合 → 更新底部状态栏（"当前回合 ●黑方落子 · 第 N 手"）
- [ ] 胜负判定 `checkWin(r, c)`：只从最后一手出发查 4 个方向连子数（横 / 竖 / 两斜），返回五连坐标；棋盘下满 225 手判平局
- [ ] 胜利表现：五连棋子高亮闪烁（定时重绘）+ 朱红连线贯穿 → 延迟 0.5s 弹结算框
- [ ] 结算弹窗（复用 common.js 的 modal）：胜方 / 用时 / 总手数 + [再来一局]（原地重置）/ [复盘] / [返回]
- [ ] 三个操作按钮：
  - [ ] 悔棋：弹历史最后一手并重绘（本地双人默认悔 1 手）；无子或已结束时置灰
  - [ ] 求和：确认弹窗 → 同意则按平局结算
  - [ ] 认输：确认弹窗 → 当前方判负，走结算流程
  - [ ] 顶部 [←退出]：对局中退出需二次确认，防止误触
- [ ] 复盘模式（可放到 M4 做）：结算后进入，用历史数组逐手回放，配上一步/下一步按钮
- [ ] **验收**：完整下一盘棋，横竖斜各赢一次都正确高亮；悔棋/求和/认输/计时/结算全链路无 bug；刷新页面可重开局

### M3 · 页面拼装（约 1 天）

- [ ] `index.html`：
  - [ ] 顶部用户条：一期为"游客 · 点击登录"状态（点击跳 login.html，登录本身三期才通）
  - [ ] 模式卡片：**本地双人**可点亮进入 game.html；在线模式 / 人机对战 / 挑战 AI 显示灰色 + "敬请期待"角标
  - [ ] 底部导航：排行榜 / 战绩 / 设置（设置做成弹窗：音效开关即可；"任务"按设计砍掉）
- [ ] `game.html`：顶部栏（退出 / 计时 / 规则弹窗）+ 双方信息条 + 棋盘 + 底部状态与操作按钮，接通 M1/M2
- [ ] `login.html`：表单骨架 + 前端非空校验，提交后提示"三期开放"（页面就位，逻辑后补）
- [ ] `rank.html`：榜单列表结构 + "暂无数据 · 等待后端接入"空态（含"我的排名"底栏占位）
- [ ] `history.html`：战绩列表结构 + 空态占位
- [ ] `api.js`：先立骨架——统一 `request()` 封装 + mock 数据开关（`USE_MOCK = true`），把将来要对接的接口名列全：`login / register / getUser / getRank / getHistory / submitResult`，页面一律通过它取数
- [ ] **验收**：从首页进本地双人 → 完整对局 → 结算 → 返回首页，全流程闭环；其余页面均可打开、有正确占位态、导航高亮正确

### M4 · 打磨与自测（约 0.5 天）

- [ ] 复盘模式补完（若 M2 未做）
- [ ] 音效开关落库（localStorage），设置弹窗可切换
- [ ] 响应式过一遍：360 / 375 / 414 / 480 / PC 宽屏，确认棋盘格子在最小屏上 ≥ 20px 仍好点
- [ ] 细节检查：双击不缩放、长按不呼出菜单、弹窗出现时背景不可滚动、结算后再来一局状态完全干净
- [ ] 控制台无报错，代码里临时 console.log 清理
- [ ] **验收**：拿手机实际玩一局，体验顺畅即可发布一期

## 三、二期及以后（现在只需"不挡路"，不展开）

| 期 | 前端要做的事 | 一期需要预留的钩子 |
|---|---|---|
| 二期·接后端 | 胜负判定、对局提交改走 API；战绩页接真实数据 | api.js 接口名定好、game.js 判定函数收敛在一处 |
| 三期·用户系统 | 登录注册联通、首页显示昵称积分、结算加积分变动 | login 表单骨架、用户条组件化、token 存取位置约定 |
| 四期·在线对战 | 匹配、锁盘等待态、实时同步（轮询或 WebSocket） | board.js 已有 lock()；状态栏已支持"等待对方…"文案位 |

## 四、风险与注意点

1. **Canvas 高清屏发糊** —— 必须在 M1 第一天就处理好 dpr，后补要重写坐标换算。
2. **手机上点不准 / 点棋盘页面跟着滚** —— 最近交叉点吸附 + canvas `touch-action: none`，M1 验收项。
3. **音效自动播放被浏览器拦截** —— 只在用户点击落子这个手势内播放，不做背景音乐。
4. **计时器切后台不准** —— 一律 `Date.now()` 差值，不用累加。
5. **悔棋语义** —— 本地双人先按"悔 1 手"实现；在线模式将来是"发请求等对方同意"，两者 UI 复用、逻辑分开。
