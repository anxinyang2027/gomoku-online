## 一、项目现状盘点

### 1.1 前端（已完成，不动的部分）

- 原生 HTML/CSS/JS 多页面：index / game / login / rank / history / shop，移动端优先 480px。
- 15×15 Canvas 棋盘（board.js 纯渲染）、对局逻辑（game.js）、残局挑战 300 关（puzzle.js + puzzles-data.js）。
- **分层契约已给后端留好位置**：
  - 页面一律走 `Api.*` 函数取数，不直接碰 fetch；接后端只改 `request()` 的实现，接口签名不动。
  - `USE_MOCK = true` 总开关，接后端时置 false 即切换。
  - `game.js` 的 `checkWin`（M2.6）是胜负判定唯一入口，"二期挪后端时只动它"。
  - shop / puzzles 数据形状已定死（api.js doc 注释），卡片 `data-skin-id` 钩子已留。

### 1.2 后端（houduan/，现在几乎为空）

- Maven `pom.xml`：仅 Java 21 编译配置，无任何依赖。
- `src/main/java/cn/edu/szpu/Main.java`：Hello World 脚手架。

### 1.3 前端约定下后端必须遵守的边界

| 约束 | 来源 | 后端对策 |
|---|---|---|
| `/api/*` 接口名与返回形状不能变 | api.js 接口清单 | 本计划书第四节逐接口冻结形状 |
| 响应可能是 `{code, data}` 包裹，由前端 request() 解包 | api.js 注释 | 采用统一包裹（见 2.3），前端 request() 加 3 行解包 |
| rank 行形状 `{name, score}` 降序 | rank.html 渲染代码 | 附加字段允许（前端只读这两键），顺序必须降序 |
| history 行形状 `{win, opponent, time, moves}` | history.html 渲染代码 | `time` 为 `mm:ss` 用时字符串；`win` 布尔 |
| shop 商品 `{id, cat, name, price, colors, [glyph], [img]}` | shop.html 直接消费 | 种子数据 = 现 MOCK 23 条原样搬库 |
| puzzles 返回 `{easy:[×100], hard:[×100], hell:[×100]}` | puzzle.js 直接消费 | 关卡对象形状与 puzzles-data.js 完全一致 |
| CORS：前端经 http-server(:8000) 或 file:// 打开 | 验收清单 M4.6 | Spring 全局 CORS 放开（开发期 allow all） |

## 二、技术选型与总体架构

### 2.1 技术栈（决策记录）

| 项 | 选择 | 理由 |
|---|---|---|
| 语言/运行时 | Java 21 → **编译目标改 17**（H0 决策） | 本机默认 JDK 是 17（Maven 跑在 17 上），17 编译零功能差异且不依赖环境变量；Spring Boot 3.3 完整支持 |
| 框架 | Spring Boot 3.3.5 | 生态一键装配；3.x 要求 17+，17/21 均可 |
| ORM | MyBatis-Plus 3.5.x | 国内资料多、CRUD 少写样板；Spring Data JPA 备选 |
| 数据库 | MySQL 8.0 + utf8mb4 | 生态成熟、资料多；InnoDB 事务 |
| 鉴权 | JWT（jjwt 0.12.x）| 无状态、前端只存一个 token；不引入完整 Spring Security，仅 spring-security-crypto 的 BCryptPasswordEncoder 存密码 |
| 实时通信（四期） | spring-boot-starter-websocket | 在线对战实时同步；标配 STOMP |
| 工具 | Lombok、spring-boot-starter-validation | 少写 getter/校验样板 |

pom 依赖序：`spring-boot-starter-web` → `starter-websocket`（四期再加）→ `mybatis-plus-spring-boot3-starter` → `mysql-connector-j` → `jjwt-api/impl/jackson` → `spring-security-crypto` → `lombok` → `starter-validation`。

### 2.3 统一响应包裹（决策记录）

所有接口返回 `{"code": 0, "data": ..., "msg": "ok"}`；`code=0` 成功，401 未登录 → code 401，403/404/500 同理。业务数据放 `data`。

前端 `request()` 仅需追加（api.js，一期不动的部分零改动）：

```js
const res = await fetch(Api.BASE + path, {…});        // BASE='http://localhost:8080'
if (!res.ok) throw new Error('HTTP ' + res.status);
const pkg = await res.json();                          // ← 解包三行
if (pkg.code !== 0) throw new Error(pkg.msg || 'ERR ' + pkg.code);
return pkg.data;
```

## 三、数据库设计（MySQL 8）

### 3.1 ER 一览

```
user 1──n game_record（user_id 参战方）
user 1──n user_item ──1 shop_item（购买/在用）
user 1──n user_puzzle_progress ──1 puzzle
```

puzzle、shop_item 为"配置表"（种子预置）；game_record 为核心流水表；排行榜 = user.score 降序。

### 3.2 建表 DDL（init.sql 全量，utf8mb4）

```sql
CREATE DATABASE IF NOT EXISTS gomoku DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;
USE gomoku;

-- 1. 用户表（三期核心；二期即建好，种子测试号供 rank 验收）
CREATE TABLE user (
  id            BIGINT AUTO_INCREMENT PRIMARY KEY,
  name          VARCHAR(20)  NOT NULL COMMENT '用户名(登录用)',
  password      VARCHAR(60)  NOT NULL COMMENT 'BCrypt 散列',
  score         INT          NOT NULL DEFAULT 1000 COMMENT '积分(排行依据)',
  coins         INT          NOT NULL DEFAULT 500 COMMENT '金币(五期商城)',
  stone_id      VARCHAR(32)  NOT NULL DEFAULT 'stone-yunzi' COMMENT '在用棋子皮肤',
  board_id      VARCHAR(32)  NOT NULL DEFAULT 'board-default' COMMENT '在用棋盘皮肤',
  avatar_id     VARCHAR(32)  NULL COMMENT '在用头像(缺省=默认SVG)',
  created_at    DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  last_login    DATETIME     NULL,
  UNIQUE KEY uk_name (name)
) COMMENT='用户';

-- 2. 对局记录表（二期上报核心；排行榜/战绩唯一数据源）
CREATE TABLE game_record (
  id            BIGINT AUTO_INCREMENT PRIMARY KEY,
  user_id       BIGINT       NOT NULL,
  mode          VARCHAR(10)  NOT NULL COMMENT 'local / online(四期)',
  color         TINYINT      NOT NULL COMMENT '我执色 1黑 2白',
  result        TINYINT      NOT NULL COMMENT '1胜 0平 -1负',
  opponent      VARCHAR(20)  NOT NULL COMMENT '对手显示名(本地=黑方/白方)',
  opponent_id   BIGINT       NULL COMMENT '在线模式对端用户',
  moves         SMALLINT     NOT NULL COMMENT '总手数',
  duration_sec  SMALLINT     NOT NULL COMMENT '用时(秒)',
  history       JSON         NULL COMMENT '落子序[{r,c,color}…](复盘用)',
  created_at    DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  KEY idx_user_time (user_id, created_at),
  KEY idx_user_score (user_id)
) COMMENT='对局记录';
-- 注意：score 不落 JSON 而存 user 表冗余积分，排行直接 ORDER BY user.score

-- 3. 商城商品表（五期点亮；形状=api.js MOCK 23 条）
CREATE TABLE shop_item (
  id            VARCHAR(32)  PRIMARY KEY COMMENT '如 stone-yunzi',
  cat           VARCHAR(8)   NOT NULL COMMENT 'board/stone/avatar',
  name          VARCHAR(20)  NOT NULL,
  price         INT          NOT NULL DEFAULT 0 COMMENT '金币,0=默认款',
  colors        JSON         NULL COMMENT '{"--board":"#E8C286",…}',
  glyph         VARCHAR(8)   NULL COMMENT '头像字符(无图回落)',
  img           VARCHAR(128) NULL COMMENT '预览图相对路径'
) COMMENT='商城商品';
-- 种子：把 api.js MOCK '/api/shop' 的 23 条 1:1 搬入（棋盘6/棋子10/头像7）

-- 4. 用户道具表（五期：购买与"使用中"）
CREATE TABLE user_item (
  user_id       BIGINT      NOT NULL,
  item_id       VARCHAR(32) NOT NULL,
  in_use        TINYINT     NOT NULL DEFAULT 0 COMMENT '当前使用中(每cat唯一,代码保证)',
  created_at    DATETIME    NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (user_id, item_id)
) COMMENT='用户已购商品';

-- 5. 残局关卡表（H4 起接通；此前 puzzles 仍走前端本地文件）
CREATE TABLE puzzle (
  id            VARCHAR(16) PRIMARY KEY COMMENT '如 hell-42',
  mode          VARCHAR(8)  NOT NULL COMMENT 'easy/hard/hell',
  sort_no       SMALLINT    NOT NULL COMMENT '关号',
  name          VARCHAR(20) NOT NULL,
  flavor        VARCHAR(10) NOT NULL COMMENT '一步胜…五步胜',
  hint          VARCHAR(60) NOT NULL,
  preset        JSON        NOT NULL COMMENT '[{r,c,color}…]',
  steps         JSON        NOT NULL,
  UNIQUE KEY uk_sort (mode, sort_no)
) COMMENT='残局关卡(种子=puzzles-data.json 300关)';

-- 6. 残局进度表（H4.3 起进度上云；此前存 localStorage）
CREATE TABLE user_puzzle_progress (
  user_id       BIGINT   NOT NULL,
  puzzle_id     VARCHAR(16) NOT NULL,
  cleared_at    DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (user_id, puzzle_id)
) COMMENT='残局通过记录';

-- 演示种子（散列为占位符，不可直接登录；真实测试号建议用注册接口创建）
INSERT INTO user (name, password) VALUES
 ('demo',  '$2a$10$REPLACE_WITH_REAL_BCRYPT'),
 ('alice', '$2a$10$REPLACE_WITH_REAL_BCRYPT'),
 ('bob',   '$2a$10$REPLACE_WITH_REAL_BCRYPT');
UPDATE user SET score = 1200 WHERE name='demo';
```

要点：所有字符串 `utf8mb4`；JSON 列存"落子序 / 皮肤色组 / 关卡谱"，**不对 JSON 内部建索引**；排行只走 `user.score`；复盘大数据（history JSON ≤0.5KB）保留供五期以后做云端复盘。

### 3.3 积分规则（初版，四期可换 Elo）

胜 +20 / 平 +5 / 负 −10，下限 0，初始积分 1000。金币：注册送 500，每获胜一局 +20（商城点亮前只积累不开销）。积分与金币规则各自封装在 `ScorePolicy` / `CoinPolicy` 单类，四期在线模式换 Elo 只改 ScorePolicy。

## 四、接口契约（逐接口冻结）

> 形状与 `api.js` 一致；下列"响应"均指包在 `{code,data}` 里 `data` 的内容。

### 4.1 二期（对局 + 排行 + 战绩）

| 方法 | 路径 | 说明 | 请求 | 响应 |
|---|---|---|---|---|
| POST | /api/result | 上报对局 | {winner:0\|1\|2, moves:int, timeMs, color?:1\|2, opponent?:str, history?:[{r,c,color}]} | {scoreDelta, score} |
| GET | /api/rank | 总榜 | ?limit=50 | [{name, score, rank, id}] 降序 |
| GET | /api/rank/me | 我的排名 | —（未登录返回 null） | {rank, score} 或 null |
| GET | /api/history | 我的战绩 | ?page&size=20 默认20 | [{win, opponent, time:'mm:ss', moves, date:'YYYY-MM-DD hh:mm'}] 新在前 |

约定：
- `history` 行必含四键（win/opponent/time/moves），`date` 为扩展字段（当前前端只拼前四键）
- `rank` 附加 rank/id 字段均允许（前端只读 name/score）；顺序必须是 **score 降序**
- **决策记录：登录/注册随二期一并交付**（rank/history 需要用户身份归属）。三期做"体验细化"：首页昵称注入、结算积分变动展示、token 静默刷新，不改接口签名。

服务端校验（判胜唯一入口后移）：`Referee.checkWin(grid, r, c)` 复用 game.js M2.6 同源算法，在 `history` 全序列上**重放判定**；重放结果与上报 winner 不一致 → 整条拒收（code 4002），防止改包刷分。

### 4.2 三期(用户系统)

| 方法 | 路径 | 请求 | 响应 |
|---|---|---|---|
| POST | /api/register | {name, password} | {id, name, score} |
| POST | /api/login | {name, password} | {id, name, score, coins, token} |
| GET | /api/user | —(token) | {id, name, score, coins, skins:{stone,board,avatar}} |

- 注册规则：name 1–20 字符去重；password 6–40；BCrypt 存储；重名 code 1001"用户名已存在"。
- JWT：HS256，24h；`Authorization: Bearer <token>`。前端 login.html 成功后 `localStorage.setItem('gomoku.token')`，request() 统一带上 → 401 时清 token 回 login。
- 首页数据注入：调 getUser → 填 `#user-name`、`#user-score`（前端 M3.2 数据位）。

### 4.3 商城与残局只读接口（H4 接通；二期不实现，暂走前端本地数据）

| 方法 | 路径 | 请求 | 响应 |
|---|---|---|---|
| GET | /api/shop | — | [{id,cat,name,price,colors?,glyph?,img?}] |
| GET | /api/puzzles | — | {easy:[…×100], hard:[…], hell:[…]}（同 puzzles-data.js 形状） |
| GET | /api/puzzle/progress | — | {cleared:['easy-1', …]}（未登录 []） |
| POST | /api/puzzle/progress | {puzzleId} | {cleared:[…]} |

shop 商品 = 种子 23 条零变形；puzzle = 初始化种子，`resources/db/puzzles-seed.json` 由 `tools/gen-puzzles.js` 转出一份 JSON，服务端启动读一次进内存（300 关纯静态）。

### 4.4 四期（在线对战，WebSocket 预留）

- `/ws`：STOMP，`/app/match.rush`（报名）、`/app/move`（落子，服务端 Referee 复核后广播）、`/app/room.join`。
- 匹配池 `Map<userId, 玩家>`；房间 2 人 + 先手骰；30s 无应答断线判负；落子超时 30s。
- **四期开工才动此节；二期一切照旧、不碰 WebSocket。**

### 4.5 五期（商城点亮：购买与换肤）

| 方法 | 路径 | 请求 | 响应 |
|---|---|---|---|
| POST | /api/shop/buy | {itemId} | {coins, owned:true} |
| POST | /api/user/skin | {itemId} | {skins:{stone,board,avatar}} |

- buy 事务：金币足够 → 扣 coins + 插 user_item；不足 code 2001"金币不足"，已拥有 code 2002。
- skin：同一 cat 只允许一个在用（先清旧再置新）；默认款（price=0）无需购买即可用。

## 六、前后端联调工作流

1. 后端起服务（8080），前端 `npx http-server -p 8000` 起 gomoku-web。
2. api.js `USE_MOCK=false` + `BASE='http://localhost:8080'` 一次性切真。
3. Chrome DevTools Network 面板先手工压三个接口（register/login/rank），确认 `{code:0,data}` 形状再动页面。
4. 对局上报：本地随便下 3 手认输 → 查 game_record 落库与 user.score 扣分。
5. 排行榜前端显示与 `SELECT name,score FROM user ORDER BY score DESC LIMIT 50` 一致即通过。（决策记录：以列表行降序形状冻结，前端渲染零改动，顺序正确性是核心验收点。）

## 七、风险清单与对策

| # | 风险 | 对策 |
|---|---|---|
| 1 | **file:// 打开时 fetch 跨域 null origin** | 联调只用 http-server（不以 file 起真数据）；CORS allow-all 开发期兜底 |
| 2 | **前端形状与后端不一致**（rank 顺序/键名错） | 契约以第四节冻结为准；后端接口先写集成测试再联调 |
| 3 | checkWin 前后端算法漂移 | 后端 Referee 与 game.js M2.6 一句一句同源实现 + 验收清单 M2.15 的六连用例写成 JUnit |
| 4 | 密码泄露/明文存储 | 只用 BCrypt；init.sql 的演示号是占位散列，上线前删除 |
| 5 | 事务完整性（购皮肤/记分两条写）| 两个写操作一个事务 + Service 层声明 @Transactional |
| 6 | JSON 列被误当索引用 | 约定：排行/战绩查询不走 JSON 列；只经 user.score 与 game_record 既有列索引 |
| 7 | token 泄露/长期有效 | 24h 过期；后续加 refresh 接口（三期细化项） |
| 8 | 在线对战状态机复杂 | 二期不碰（H6 明确隔离），降低回归面 |
