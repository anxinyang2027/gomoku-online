# 五子棋前端开发任务规划 · 细化版

> 由 test.txt 细化而来：阶段划分（M0–M4）、全局约定、风险清单全部不变，
> 只把"任务分解"从里程碑级拆到任务级，共 **56 项**。
> 使用方式：每个任务有编号、可勾选、能独立验收；**任务顺序即依赖顺序**，

## 一、全局技术约定（与 test.txt 一致，保留以便单文件查阅）

| 项 | 约定 |
|---|---|
| 技术栈 | 原生 HTML / CSS / JS（ES6+），无框架、无构建工具，双击 index.html 即可运行 |
| 页面结构 | 多页面：index / game / login / rank / history |
| 布局 | 移动端优先，页面容器 `max-width: 480px` 居中，PC 两侧深灰留黑边 |
| 配色 | 背景 `#2B2B2B`；棋盘 `#E8C286`；黑子 `#1A1A1A` / 白子 `#F8F8F8`；强调朱红 `#C0392B` |
| 色彩管理 | 全部颜色走 `style.css` 顶部的 CSS 自定义属性（`--bg`、`--board`、`--accent`…），一处改全局生效 |
| 棋盘 | 15×15，Canvas 绘制，`devicePixelRatio` 适配保证高清屏不糊 |
| 事件 | 统一用 Pointer Events（鼠标 + 触摸一套代码） |
| 音效 | 优先用 Web Audio API 合成（落子"嗒"声），避免依赖素材文件；设置里可关 |
| 数据 | 一切需要后端的数据（用户、战绩、排行）在 `api.js` 里留 mock 接口，页面只调接口不关心来源 |

**目录结构**（按 1.txt）：

```
gomoku-web/
├── index.html      首页
├── game.html       对局页（核心）
├── login.html      登录/注册
├── rank.html       排行榜
├── history.html    战绩
├── css/style.css
├── js/
│   ├── board.js    Canvas 棋盘绘制与交互（纯渲染，不含规则）
│   ├── game.js     对局逻辑（规则、回合、胜负）
│   ├── api.js      fetch 接口封装（一期全部是 mock）
│   └── common.js   弹窗、toast、用户信息条、底部导航等公共组件
└── assets/         图标（尽量用内联 SVG，少放文件）
```

**分层原则**：`board.js` 只管"画"和"点哪了"，不知道规则；`game.js` 只管规则和状态，通过回调驱动 board。这样二期把判定挪到后端时，board 一行不改。

### M1 · 棋盘渲染与交互 board.js（15 项 · 约 1 天，核心难点）

目标：一块清晰、可点、有动画的棋盘；board.js 全程不知道"规则"二字。

- [x] **M1.1 先定对外接口再填肉**：`new Board(canvas, opts)`；方法 `draw(stones, last)`、`highlightWin(cells)`、`lock() / unlock()`、`setPreviewColor(color)`；事件 `onCellClick(cb)`、`onHover(cb)`；stones / cells 统一 `[{r, c, color}]` 格式。——先写空壳 + 注释占位，后续任务逐项实现；M2 的 game.js 对着这份接口写
- [x] **M1.2 画布尺寸与常量**：读父容器宽度定正方形边长；算出边距 margin 与格宽 `cell = (边长 − 2×margin) / 14`；`window.resize` 时重算并重绘；margin / cell 提出来当常量（画子、换算都要用）
- [x] **M1.3 HiDPI 适配**：`canvas.width = cssSize × dpr`、`ctx.scale(dpr, dpr)`，之后全部按 CSS 像素坐标画；临时把 dpr 强制为 1 / 2 / 3 各看一遍，线与棋子必须都清晰——**本项不过关不进 M1.4**（后补要重写坐标换算）
- [x] **M1.4 棋盘底色与外框**：木色 `#E8C286`，全部在 canvas 内绘制（不走 CSS 背景，统一 redraw 逻辑）；最外一圈加粗边框线
- [x] **M1.5 网格线**：15 横 + 15 竖细线；dpr=1 时坐标取整（或 0.5 偏移），避免 1px 线发糊
- [x] **M1.6 星位**：(3,3)(3,11)(11,3)(11,11)(7,7) 五个实心小圆点，天元 (7,7) 略大
- [x] **M1.7 坐标换算**：`pxToCell(x, y)` → 最近交叉点 `{r, c}`（直接取最近，无需容差判断）；`cellToPx(r, c)` → 交点像素中心。点击、hover、画子、连线全走这一对函数，不许各写一套
- [x] **M1.8 画棋子**：黑子 `#1A1A1A` + 左上径向渐变高光；白子 `#F8F8F8` 微灰渐变 + 深色细描边（木色上白子必须有边才看得清）；直径 ≈ 0.9 × cell
- [x] **M1.9 落子动画**：新子 150ms 缩放 1.3 → 1.0（easeOut，requestAnimationFrame 驱动）；`draw()` 全量重绘不播动画
- [x] **M1.10 最后一手标记**：最新一颗子上叠朱红小圆点，由 draw 的 `last` 参数控制
- [x] **M1.11 hover 预览**：仅 `pointerType === 'mouse'`、格点为空、未锁盘三个条件同时满足时，画半透明当前色棋子（颜色来自 `setPreviewColor`）；移出画布或格点已占即清除；同时通过 `onHover` 通知 game.js
- [x] **M1.12 落子点击**：`pointerup` 触发（比 pointerdown 抗误触，按下后滑出画布可取消）；canvas 上 `touch-action: none`；锁盘状态点击无效
- [x] **M1.13 胜利高亮 `highlightWin(cells)`**：五连子加描边强调 + 首尾贯穿朱红直线；闪烁 3 次后定格（内部 setInterval，用完自清）
- [x] **M1.14 临时联调页**：game.html 写临时脚本——点击落子、黑白固定轮换，逐项验证 M1.2–M1.13 的表现；**M3.8 接真逻辑时删除**
- [ ] **M1.15 ✅ 里程碑验收**：PC + 手机模拟器下棋盘线条、棋子清晰不糊；点交叉点附近必中最近点；hover 预览出现/消失正常；最后一手红点在；resize 不穿帮

### M2 · 对局逻辑 game.js（15 项 · 约 1 天）

目标：完整正确的本地双人；board.js 一行不改。

- [x] **M2.1 状态与重置**：`board[15][15]`（0 空 / 1 黑 / 2 白）、`history[]`（落子记录）、当前执子方、手数、`startTime`、`gameOver` 标记；`newGame()` 一键复位全部状态（M4.4"再来一局洁净"的保证）
- [x] **M2.2 初始化接线**：game.html DOMContentLoaded → `new Board()` + `new Game()`；Game 订阅 board 的 `onCellClick / onHover`；每次换手调 `setPreviewColor` 同步预览颜色
- [x] **M2.3 落子主链路**：点击 → 校验（未结束 / 未锁 / 空位，否则忽略）→ 写数组 + history.push → `board.draw`（含动画）→ 音效（M2.14 接入，先留调用位）→ 胜负检查（M2.6 接入，先留调用位）→ 未分胜负则换手 → 刷新状态栏
- [x] **M2.4 底部状态栏**："当前回合 ●黑方落子 · 第 N 手"，每次落子后同步
- [x] **M2.5 计时器**：**进对局页即开始计时**；用 `Date.now() − startTime` 差值换算 mm:ss，setInterval 500ms 只刷显示文案、不做累加；对局结束停表；切后台回来依然准确
- [x] **M2.6 胜负判定 `checkWin(r, c)`**：只从最后一手出发，横 / 竖 / 两斜 4 个方向向两侧数连子，≥5 返回连子坐标数组（供 M1.13 高亮）
- [x] **M2.7 平局判定**：`history.length === 225` → 按平局走结算
- [x] **M2.8 胜利表现**：调 `board.highlightWin(cells)` → 500ms 后弹结算框
- [x] **M2.9 结算弹窗**：胜方（朱红强调）/ 平局文案 + 用时 + 总手数；按钮 [再来一局]（newGame + 重绘 + 关弹窗）/ [复盘]（**一期置灰，M4.1 做完激活**）/ [返回]（回首页）
- [x] **M2.10 悔棋**：history 弹出最后一手 → 清对应数组格 → 重绘，手数、执子方同步回退；history 为空或 gameOver 时按钮置灰。本地双人固定悔 1 手（在线模式的"请求-同意"语义四期另做，UI 复用）
- [x] **M2.11 求和**：确认弹窗"同意后按平局结算？" → 同意 → 按 M2.9 平局分支结算；取消关闭
- [x] **M2.12 认输**：确认弹窗 → 当前执子方判负 → 走 M2.9 结算
- [x] **M2.13 退出确认**：对局中（已 ≥1 手且未结束）点 [←退出] → 二次确认弹窗；已结束或零手直接返回首页
- [x] **M2.14 落子音效**：Web Audio 合成短促"嗒"声（快速衰减正弦 + 噪声瞬态）；AudioContext 在首次用户手势里创建 / resume（避开自动播放拦截）；接入 M2.3 调用位；播放前读设置开关（开关本体 M3.5 才接通，此前默认开）
- [ ] **M2.15 ✅ 里程碑验收**：横 / 竖 / 两斜各真实赢一次，高亮与连线全对；平局逻辑用"临时把连子阈值改成 2 + 手动摆子"或直接构造棋盘数组单测 checkWin（225 手真下满不现实）；悔棋 / 求和 / 认输 / 退出确认 / 计时全链路无 bug；刷新页面 = 干净新局

## 四、风险与注意点（对应到任务）

1. **Canvas 高清屏发糊** —— M1.3 第一时间处理，验收不过不往下走，后补要重写坐标换算
2. **手机上点不准 / 点棋盘页面跟着滚** —— 最近交叉点吸附（M1.7）+ canvas `touch-action: none`（M1.12），M1.15 验收项
3. **音效自动播放被浏览器拦截** —— AudioContext 只在用户手势内创建（M2.14），不做背景音乐
4. **计时器切后台不准** —— 一律 `Date.now()` 差值，不用累加（M2.5）
5. **悔棋语义** —— 本地双人按"悔 1 手"实现（M2.10）；在线模式将来是"发请求等对方同意"，两者 UI 复用、逻辑分开
